# 10a-amplify-smoke-test-improvements

## 目的

Amplify限定ベータ環境の2プレイヤースモークテストで見つかった操作性と視認性の問題を改善し、初見のプレイヤーでも盤面の状態と次の操作を理解できる状態にします。

カスタムドメイン、DNS、SSL、正式公開向けCORSには進まず、既存のAmplify URLで再テストできる品質を先に整えます。

## スモークテスト結果

2プレイヤーでゲーム開始から対戦結果まで進行できました。ゲームの基本フローは成立していますが、次の課題が見つかりました。

### 進行と誤操作

- 現在の手番とフェーズが盤面から分かりにくい
- カードを出した後の「手番終了」を見落とし、両者が待つことがある
- カードを1回押すだけで選択でき、誤タップへの不安がある
- 獲得カード選択と捨て札トップ選択の案内が操作場所から離れている
- ラウンド勝者が分からない

### レイアウトと重なり

- デスクトップの初期表示で両者の手札と中央盤面を一望できない
- プレイヤー名、マーカー、星明りの縦方向占有が大きい
- ルールと音設定がカードより背面に入り、音設定は他UIと重なる
- ロビー見出しの改行位置が不自然
- スマートフォン表示は未テスト

### 状態変化と結果

- 黒い星の移動が視覚的に伝わらない
- 星明りが闇へ変わった理由を対戦中に確認できない
- カード、黒い星、星明りの状態変化が瞬間的に見える
- 対戦結果から終了盤面を確認できない
- 収集台帳のカードが小さく、数字を判別しづらい
- カードの数字と宝石が小さい

### 説明と音

- 現在のルール表示だけでは初回プレイヤーがルール全体を理解できない
- ラウンド勝利、ゲーム勝利、星明り反転などの効果音を増やしたい
- 相手の接続状態を確認できるとよいが、MVPでは必須ではない

## 実装方針

- 既存の`design.md`とカード・トークン画像を維持する
- 琥珀色は現在手番、現在操作、選択、主要確定だけに使用する
- 状態説明を左レールだけに置かず、操作ドックの直上でも提示する
- CSSによる短い演出だけを使い、`prefers-reduced-motion`を尊重する
- APIで取得できない情報を推測表示しない
- 接続状態はサーバー側のpresence設計が必要なため、今回の必須範囲から外す

## 実装単位

### A1. オーバーレイとロビー

- ルールを最上位レイヤーのモーダルとして表示する
- 音設定をモーダル化し、背景操作と重なりを防ぐ
- ダイアログ表示中は本文スクロールを止める
- ロビー見出しの改行位置を意図的に固定する

### A2. カードの二段階操作

- 1回目の押下でカードを持ち上げて選択する
- 同じカードの2回目の押下、または確定ボタンで操作を送信する
- 別カードを押した場合は選択を変更する
- 選択中の説明を操作ドックへ表示する

### A3. 手番終了導線

- `canEndTurn`時だけ手番終了を強くハイライトする
- 「カードを出したら自動で手番終了」を設定できる
- 自動終了設定には「プレイ後の追加ドローを行わない」ことを明記する
- 設定はブラウザへ保存する

### B1. デスクトップ盤面

- 盤面をビューポート高へ収めやすい密度へ調整する
- プレイヤー名、手札枚数、スタートマーカー、黒い星、星明りを同じ要約行へ集約する
- 相手の手札、中央盤面、自分の手札の高さを抑える
- 収集台帳のカードを判別可能な大きさへ拡大する

### B2. 状態案内

- 現在手番のプレイヤー領域をハイライトする
- 自分の手番開始と選択フェーズ開始を自動で消える通知で示す
- ラウンド終了を状態差分から検出し、勝者を通知する
- 操作ドック内にも現在の操作文を表示する

### B3. 結果確認

- 対戦結果に「盤面を確認する」を追加する
- 結果を閉じても終了済み盤面は操作不能のまま維持する
- ロビーへ戻る操作は常に残す

### C1. 状態変化の演出と履歴

- 黒い星画像を所有者名の近くへ置く
- 黒い星の所有者変更を短い移動・到着演出で示す
- カードを場へ出す演出を滑らかにする
- 星明り反転を強調する
- クライアントで確実に判定できる状態差分を対戦履歴として表示する

### C2. 効果音

- 自分の手番、ラウンド結果、星明り喪失、ゲーム勝敗を別の音型にする
- 音設定を維持し、初期状態では従来どおり効果音を無効にする

### D1. 完全版ルール

- ゲーム目的、カード、準備、リード、トランプ、スーパートランプを説明する
- ラウンド進行、ダミー、休憩カード、星明り、補充、勝利条件を説明する
- 画面操作とゲームルールを分けて説明する

### D2. レスポンシブ確認

- 320px、375px、414px、768pxで横スクロールと操作不能がないことを確認する
- 手札だけを意図的な横スクロール領域にする
- ダイアログ、操作ドック、カード選択をタッチで利用できるようにする

## 完了条件

- lint、typecheck、test、buildが成功する
- 主要な状態案内と二段階カード操作に自動テストがある
- ルールと音設定が盤面より前面に表示され、他UIと重ならない
- 現在手番、次の操作、ラウンド結果が盤面付近で分かる
- 対戦結果から終了盤面を確認できる
- デスクトップの標準的な高さで盤面全体を把握しやすい
- 320px、375px、414px、768pxで致命的な重なりや画面全体の横スクロールがない
- 改善内容を既存Amplify URLへ反映する前の差分として確認できる

## 実装結果

2026-08-10時点で、ローカル実装と自動検証を完了しました。

- A1: ルール・音設定をポータル型モーダルへ変更し、ロビー見出しの改行を固定した
- A2: カードを「1回目で選択、同じカードの2回目または確定ボタンで実行」に変更した
- A3: 手番終了を強調し、追加ドローを行わない場合の自動終了設定を追加した
- B1: デスクトップ盤面を圧縮し、プレイヤー情報と星明りを同じ要約行へまとめた
- B2: 手番・選択フェーズ・ラウンド結果を盤面付近の通知と履歴で示すようにした
- B3: 対戦結果を閉じて終了盤面を確認し、結果を再表示できるようにした
- C1: 黒い星、カード着地、星明り反転の短い演出と対戦履歴を追加した
- C2: 手番、ラウンド、星明り喪失、ゲーム勝敗で異なる効果音を割り当てた
- D1: 初回プレイヤー向けに準備から勝利判定までのルール説明を拡充した
- D2: 320px以上で全体の横スクロールを避け、手札を意図的な横スクロール領域として維持した
- カードの数字、宝石、収集台帳の表示を拡大した

検証結果:

- `npm run lint`: 成功
- `npm run typecheck`: 成功
- `npm test -- --run`: 37件成功
- `npm run build`: 成功

残作業は、Amplifyへ反映した後のデスクトップ2ユーザー再スモークテストと、320px、375px、414px、768pxおよび実スマートフォンでの目視・タッチ確認です。相手の接続状態はpresence APIが必要になるため、今回の実装対象外として残します。
