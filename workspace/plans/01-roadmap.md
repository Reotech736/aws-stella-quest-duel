# 01-roadmap

## 概要

このドキュメントは、MVP到達までの全体ロードマップを整理するための一次計画です。

以後の詳細計画は `workspace/plans` 配下に段階的に追加し、内容が安定したものだけを `README.md` や `docs/` 配下へ反映します。

## 計画の置き方

- 全体の見通しはこの `01-roadmap.md` で管理する
- 各テーマの詳細は個別 plan に分ける
- 命名は `番号+slug` とする
- まずは `workspace/plans` を一次保管場所とし、確定後に正式文書へ反映する

### 11. カスタムドメイン正式公開

状態: 未着手・限定ベータ完了後

目的:

- ゲーム本体を`https://stella-quest-duel.reotech736.com`で正式公開する
- `reotech736.com`の既存ブログを維持し、ブログ側のゲーム紹介ページからゲームへ案内する
- Amplify管理SSL証明書とAPI CORSをカスタムドメインへ合わせる

開始条件:

- フェーズ10の2ユーザースモークテストと運用確認が完了している
- 正式公開時のアクセス制御方針が確定している
- Amplify、DNS、CORSを変更する明示的な承認がある

主な作業:

1. Amplifyへ`stella-quest-duel.reotech736.com`を割り当てる。
2. Amplifyが提示する検証値と接続先を確認する。
3. お名前.com DNSへ必要なCNAMEレコードを追加する。
4. Amplify管理SSL証明書の発行と有効化を確認する。
5. API CORSをカスタムドメインへ変更する。
6. カスタムドメインから最終スモークテストを行う。

既存ブログの構成やDNSレコードを推測で変更しません。具体的なDNS値は、Amplifyでカスタムドメインを設定するときに提示された内容を確認してから反映します。

詳細:

- `workspace/plans/11-custom-domain-release.md`

## 依存関係

- ゲームルール整理が、MVP要件整理・データ設計・API設計の前提になる
- MVP要件整理が、画面構成整理と実装順序の前提になる
- データ設計とAPI設計は相互に影響するが、ルール整理後に並行で見直せる
- 画面構成整理は、MVP要件とAPI設計の内容を入力として扱う
- 実AWSでの基本動作確認結果を、UI改善の優先順位へ反映する
- UI改善計画の完了条件を、Amplify限定ベータ公開の開始条件とする
